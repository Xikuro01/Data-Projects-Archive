# 팰월드: 1단계부터 현재까지의 전체 진행 과정

> 본 문서는 오버데어(OVERDARE, 크래프톤의 UGC·메타버스 자회사) 데이터
> 분석가 포지션 지원을 위한 포트폴리오 서브 프로젝트 중 하나입니다.

## AI(Claude) 활용 내역

전 과정에서 Claude를 작업 도구로 활용했습니다. 역할 분담은 다음과
같고, 각 스크립트 상단 "[AI 협업 노트]"에도 개별적으로 명시돼 있습니다.

- **본인이 직접 함**: 가설 설계, 어떤 지표·시나리오를 비교할지 결정,
  패치노트·커뮤니티 게시글에서 실제 게임 변경사항 확인, 통계·데이터
  결과에 대한 최종 해석 및 지지·미지지 판단
- **Claude와 협업함**: 통계 코드(z-검정 등) 및 시각화 구현, 시뮬레이션
  로직 작성, 데이터 구조 설계, 수집 데이터의 이상치·편향 진단(예:
  up_votes 소스 오류, 표본 설계 결함 발견), 웹 스크래퍼 코드 작성,
  README 문서화 및 표현 검토

## 단계별 데이터 성격

프로젝트 전체가 같은 성격의 데이터를 쓴 게 아니라서, 어느 단계가
가상이고 어느 단계가 실데이터인지 아래에 명시합니다.

| 단계 | 데이터 성격 | 설명 |
|---|---|---|
| 1단계 (도전과제 하락폭) | 가상 데이터 | 실제 API·로그 없이 가정한 도전과제 달성률 |
| 2단계 (선택 퀘스트 효과) | 가상 데이터 | 게임에 존재하지 않는 콘텐츠를 가정한 시나리오 |
| 3단계 (정출 리스크 시나리오) | 가상 데이터 | 정식출시 전 시점이라 실측 자체가 불가능했음 |
| 4단계 (EA vs 1.0 동기곡선) | 혼합 | 이정표 시점·실제 변경사항은 실제 관찰(본인 플레이 경험 + 패치노트) 기반, 동기 점수·감쇠율은 가정치 |
| 5단계 (리뷰 SQL 파이프라인) | 합성 테스트 데이터 | `fetch_reviews_from_api()`는 구현됐으나 이 환경의 네트워크 제약으로 미실행. 현재 결과는 파이프라인 로직 검증용 합성 데이터 기준이며, 실제 리뷰로 검증된 결과가 아님 |
| 6단계 (패치 대응 정성 검증) | 실제 데이터 | 스팀 실제 리뷰 200건 + 디시인사이드 실제 게시글 300건·840건 수집 (수집 방식의 시간축 편향 등 한계는 있으나 데이터 자체는 실제 유저 게시물) |

## 최종 결과물부터 보기

- `palworld_motivation_curve.py` — EA vs 1.0 실제 재설계가 플레이 동기에
  미치는 영향 시뮬레이션 (현재 메인 결론)
- `setup_palworld_db.py` + `palworld_review_analysis.sql` + `run_palworld_sql.py`
  — "구조변경 언급 리뷰의 긍부정"을 카테고리별 z-검정까지 포함해
  검증하는 SQL 파이프라인. **현재 실행 데이터는 합성 테스트 데이터**이며,
  실제 1.0 리뷰 연동 함수는 구현만 되어 있고 본인 환경에서 실행 필요
  (자세한 내용은 아래 "단계별 데이터 성격" 표 참고)
- `dc_scraper_targeted_period.py` — 디시인사이드 팰월드 갤러리에서 1.0.3
  패치(제트래곤 안장 레벨 79→70) 관련 유저 반응을 정성적으로 수집하는
  파이프라인 (정성적 근거 확보로 이번 단계 마무리, 패치 전후 정량
  비교는 표본 한계로 다루지 않았으며 후속 후보로 남겨둠)

## 여기까지 오는 과정

### 1단계 — 도전과제 하락폭 분석 (`palworld_stage_dropoff.py`)

가장 처음 접근은 단순했습니다. 진행 단계별 도전과제 달성률을 가상으로
설정하고, 어느 구간에서 하락폭이 가장 큰지(=이탈이 잦은지)를 계산.
방법론은 명확했지만 데이터가 완전히 가상이라는 한계가 뚜렷했습니다.

### 2단계 — 선택 퀘스트 도입 효과 (`palworld_optional_quest.py`)

"선택 퀘스트를 수행한 그룹 vs 안 한 그룹"을 비교하는 A/B 형태로
전환했으나, 이 비교는 사실 아직 일어나지 않은 콘텐츠(선택 퀘스트 자체가
게임에 없음)를 있다고 가정한 시나리오였습니다.

### 3단계 — 정식출시 리스크 시나리오 (`palworld_full_release_scenario.py`)

"정식출시하면 콘텐츠가 늘어나 이탈 리스크가 커질 것이다 → 선택
퀘스트를 도입하면 완화될 것이다"라는 미래 예측형 시나리오로 재설계.
이 과정에서 **완화 효과가 증가분보다 커서 오히려 출시 전보다 이탈률이
낮아지는 논리 오류**를 발견해 파라미터를 수정했고, 참여율(선택
퀘스트를 실제로 쓰는 유저 비율)까지 반영해 정교화했습니다.

### 전환점 — 실제로 정식 출시가 일어남

검색을 통해 팰월드가 실제로 2026년 7월 10일 1.0으로 정식 출시됐고,
필드보스 재배치·신규 지역·난이도 곡선 재조정 등 실제 패치노트가
공개되어 있음을 확인했습니다. 3단계까지의 "미래 예측" 전제 자체가
무효화됐습니다.

### 4단계 — EA vs 실제 1.0 동기 곡선 (`palworld_motivation_curve.py`)

방향을 완전히 바꿔, 본인이 EA와 1.0을 모두 플레이하며 관찰한 다섯 가지
실제 변화(이동수단 지연, 고성능 요소 재배치, 경비 강화, 테크트리
재구성, 초반 밸런스 보정)를 이정표로 삼아 "재설계가 플레이 동기를
얼마나 오래 유지시키는가"를 시뮬레이션. 라이브러리 API 변경으로 인한
실행 오류(`np.trapz`→`np.trapezoid`)를 발견해 수정했고, 감쇠율·동기
점수를 각각 흔들어보는 민감도 검증도 거쳤습니다(방향성은 견고했으나,
이 견고함이 '이정표 개수 자체가 2배 늘었다'는 설계에서 상당 부분
예견된 것이라는 한계까지 정직하게 확인).

### 5단계 — 리뷰 SQL 파이프라인 구축 (합성 데이터로 로직 검증)

같은 가설을 실제 데이터로 검증할 목적으로 Steam 리뷰 API(App ID
1623730) 연동 함수까지 준비해 SQL 분석 파이프라인을 구축했습니다.
다만 이 환경에서는 실제 API 호출 없이, 카테고리별로 서로 다른 내재
신호를 심어둔 합성 테스트 데이터로 파이프라인 로직을 검증했습니다.
처음엔 테스트 데이터를
인위적으로 균형 맞춰 "차이 0.0%p"라는 무의미한 결과를 얻었으나,
이를 인지하고 카테고리별(위치재배치/테크트리순서/밸런스난이도)
세분화 + 이표본 비율 z-검정을 추가해 실제로 의미 있는 신호를
찾아내는 구조로 재작업했습니다. 민감도 검증(키워드 범위) 중에도
테스트 문구 설계 결함을 발견해 수정하는 과정을 거쳤습니다.

### 6단계 — 1.0.3 패치 대응 가설 + 디시인사이드 정성 검증 (정성 분석 완료)

정식 출시 이후 팰월드가 1.0.3 패치(2026-08-12)로 제트래곤 안장 해금
레벨을 79→70으로, 필요 재료를 세계수 전용 채굴물(팰키사이트)에서
다른 지역에서도 구할 수 있는 재료(솔라이트 주괴)로 낮췄다는 사실을
확인. 이를 계기로 가설을 구체화함:

> 1.0.0 시점엔 "제트래곤을 획득해도 안장은 79레벨(만렙 80 직전)에서야
> 풀리고, 재료도 세계수 진입이 필수"인 구조라 유저들이 사실상 레이번
> 등 대체 날탈을 쓸 수밖에 없었다. 이 구조가 의도된 것인지와 무관하게
> 실제로는 제트래곤에 대한 수요·불만이 이어졌고, 1.0.3에서 이 장벽을
> 낮췄다.

이를 검증할 데이터를 모으는 과정에서 세 번의 수집 시도가 모두 같은
함정에 반복해서 걸림 — **최신 스냅샷만 긁혀서 "패치 전/후 비교"에
필요한 시간축 자체가 확보되지 않는 문제**:

1. **스팀 리뷰 200건** (`palworld_reviews_random300_2026-09-02.csv`,
   `filter=recent` 기반) — 날짜가 8/22~9/2로
   몰려있고 제트래곤/안장 키워드 언급이 0건. 스팀 리뷰 자체가 대부분
   한 줄짜리 감상평(중앙값 13자)이라 세부 메커니즘 불만이 잘 안 남는
   매체라는 한계도 함께 확인함
2. **디시인사이드 300건** (`dc_palworld_300posts_2026-09-03.csv`,
   게시판 1페이지 기반) — 294건이 9/1~9/3
   이틀에 몰려있고 나머지는 상단 고정 공지글. up_votes도 전부 0으로
   수집됐는데, 파싱 버그가 아니라 "추천수는 목록 페이지에만 있고
   상세페이지 JSON-LD엔 없다"는 잘못된 소스 선택이 원인이었음을 확인
3. **디시인사이드 840건** (`dc_palworld_period_sampled.csv`,
   목록 페이지네이션으로 7/30~8/13 구간 타겟팅
   + 가설 키워드 우선 표본, 수집 스크립트는 `dc_scraper_targeted_period.py`)
   — 목표했던 정출 이전(~7/10) 구간은 갤러리
   활동량이 예상보다 훨씬 많아 여전히 확보하지 못했고, 표본 설계도
   키워드 매칭 건수(840건)가 목표 표본 수(300)를 이미 넘겨버려
   무작위 비교군이 0건이 되는 설계 결함이 있었음. 정량적 빈도·전후
   비교는 여전히 불가능하지만, 정성적 사례로는 지금까지 중 가장
   풍부한 자료를 확보함

**결론 — 지지되는 것과 지지되지 않는 것을 구분**

디시인사이드 840건(키워드 우선 선별 표본)을 직접 읽어 확인한 결과:

- **지지됨** — "제트래곤을 획득해도 안장 때문에 못 탄다"는 좌절은
  가정이 아니라 실제 게시글로 관측됨 (재료 부족 실시간 불만, 79렙
  확인 후 실망하는 서사형 글 등)
- **지지됨** — 제트래곤을 비판하는 게시글 중에는 "레이번이 68렙으로
  더 먼저 접근 가능하다"는 상대 비교 논리가 등장함 — 이 논리를
  명시적으로 설명하는 게시글을 확인함 (다만 이 논리가 비판 전체에서
  차지하는 비중은 표본 특성상 추정 불가)
- **지지되지만 원 가설보다 복잡함** — 레이번 선호 이유가 접근성뿐
  아니라 "제트래곤은 탑승 중 무기 사용이 제한된다"는 별개의 전투
  사용성 불만과도 얽혀 있음 — 레벨 격차 하나로 환원할 수 있는 문제가
  아님
- **지지 안 됨** — 1.0.3 패치가 문제를 "해결했다"고 단정하기는 이름.
  패치 당일 관찰된 소수 게시글(4건)에서도 레벨 조정보다 성능 버프를
  원했다는 의견과 여전히 안 탈 것 같다는 의견이 공존해, 반응이 엇갈림
  (표본이 작아 이 자체도 추가 확인이 필요한 잠정적 관찰)
- **부가 발견** — 정식출시 전 50레벨대에 제트래곤을 얻었다는 유저
  증언(작성자 본인도 "50렙이었나"라며 정확한 기억은 아니라고 언급)을
  하나 확인함 — 4단계 `palworld_motivation_curve.py`가 세운 EA vs
  1.0 전제를 뒷받침하는 정황이지만, 단일 게시글의 불확실한 기억에
  기댄 것이라 "교차검증"이라 부르기엔 근거가 약함
- **미확인** — "개발사가 다른 날탈 수요를 높이려 의도적으로 설계했다가
  되돌렸다"는 원 가설의 인과·의도 층은 공식 자료에서 근거를 찾지
  못해 여전히 추정 단계로 남음

**한계**: 840건은 제목에 가설 키워드가 포함된 글만 모은 선별 표본이라
선택 편향이 있고, 무작위 비교군이 없어 "몇 %가 이런 반응이었다"는
빈도 기반 주장은 할 수 없음. 감정 라벨도 없어 위 분류는 연구자의
정성적 판단이며 재현 가능한 통계 분류가 아님. 정량적 전후 비교를
위해서는 패치 이후 최소 2~3주 경과 시점 데이터와 별도의 무작위
비교군을 추가로 수집하는 재작업이 필요함 (다음 단계 후보).

## 이 흐름이 보여주는 것

1~3단계는 전부 "그럴듯한 가정 위의 시뮬레이션"이었고, 실제 사건
발생을 계기로 4단계에서 "실제 관찰 기반 시뮬레이션"으로, 5단계에서
"실제 데이터 연동을 목표로 한 파이프라인 구축(현재는 합성 데이터로
로직 검증)"으로 전환됐습니다. 6단계에서도 같은 패턴이 반복됐습니다 — 데이터 수집을
세 번 시도했고 매번 "최신 스냅샷만 긁힌다"는 같은 함정에 걸렸지만,
그때마다 원인을 재확인해 다음 시도를 개선했습니다. 이 과정에서
일관되게 나타난 패턴은, **인상적인 결과나 그럴듯한 설명이 나왔을 때
그대로 믿지 않고 원인을 재확인하는 것**입니다 (완화효과 초과 발견,
라이브러리 오류 발견, 균형 잡힌 테스트 데이터의 함정 발견, up_votes

발견). 여섯 단계 각각이 이전 단계의 한계를 딛고 나온 결과라는 점이
이 프로젝트의 핵심 서사입니다.

## 실행 방법

```bash
pip install numpy pandas matplotlib requests beautifulsoup4

# 4단계 — 최종 메인 시뮬레이션
cd 04_motivation_curve
python3 palworld_motivation_curve.py
cd ..

# 5단계 — 실제 리뷰 SQL 분석 (본인 환경에서, requests 설치 후 fetch_reviews_from_api 사용)

python3 setup_palworld_db.py
python3 run_palworld_sql.py
cd ..

# 6단계 — 디시인사이드 패치 전후 구간 재수집 (선택 — 이미 840건 수집 완료, 후속 확장 시)
cd 06_patch_response_dc_analysis
python3 dc_scraper_targeted_period.py
cd ..
```
