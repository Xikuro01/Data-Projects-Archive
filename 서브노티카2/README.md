# 서브노티카2 플레이어 행동 분석 — 가설 설계부터 실측 데이터 검증까지

**지원 목표**: 원래는 크래프톤 전반의 데이터 분석가(신입/연계형 인턴) 포지션을
목표로 시작한 프로젝트였으나, 현재는 목표를 구체화해 **오버데어(OVERDARE,
크래프톤의 UGC·메타버스 자회사)** 데이터 분석가 포지션 지원용으로 진행함.
개인적으로 즐겨온 게임(서브노티카 시리즈)에 대한 플레이 경험과 커뮤니티 관찰을
바탕으로 가설을 세우고, 방법론을 시연한 뒤, 실제 Steam 리뷰 데이터로 검증까지
진행한 전 과정을 순서대로 정리함.

**AI(Claude) 협업 고지**: 이 프로젝트 전 과정에서 Claude를 작업 도구로 활용함.
가설 설계, 어떤 지표로 검증할지에 대한 판단, 실제 데이터 해석, 재검증 여부·범위
결정은 본인이 직접 함. 코드 구현, 통계 검정 방법 선택에 대한 설명, 문서 초안
작성은 Claude의 도움을 받음. 각 단계 설명에는 이 구분을 `[AI 협업]` 표기로
명시함.

**데이터 성격 고지**: 각 단계마다 사용한 데이터가 가상 시뮬레이션인지 실측
데이터인지를 `[데이터]` 표기로 구분해 명시함. 실측 데이터는 6단계(및 4단계에서
구축한 파이프라인을 6단계에 적용한 부분)에서만 사용됨 — 그 외 단계는 모두
방법론 시연을 위한 가상 시뮬레이션임.

## 1단계 — 초기 가설 수립 (`01_hypotheses`)

`[데이터] 가상 시뮬레이션` · `[AI 협업] 시뮬레이션 코드 구현`

얼리액세스 진행 중 커뮤니티 반응과 직접 플레이 경험을 바탕으로 이탈 구간에 대한
3가지 가설을 세움:
- 가설1: 어그로 범위 증가로 인한 조우 빈도 상승
- 가설2: 레비아탄급 생명체 대처 수단 부재
- 가설3: 특정 심해 구간 하드웨어 병목(크래시)

세 가설 중 **가설3(심해구간 하드웨어 병목)의 이탈률 차이가 가장 크게** 나타나
우선순위가 가장 높은 요인으로 추정됨. 단, 상관관계이지 인과관계를 증명하지
않는다는 한계를 명시함.

## 2단계 — 이탈 분석 기초 버전 (`02_churn_analysis`)

`[데이터] 가상 시뮬레이션` · `[AI 협업] 시뮬레이션 코드 구현 및 카이제곱 검정 구현`

"어그로 범위가 넓은 것 같으니 낮추자"는 직관적 접근을, "조우 유형별로 이탈률이
통계적으로 유의하게 다른가?"라는 검증 가능한 질문으로 바꿔 카이제곱 검정 수행.
레비아탄급 조우 후 이탈률이 뚜렷하게 높고 통계적으로 유의함을 확인.

## 3단계 — 조우 방식 재설계 (`03_encounter_redesign`)

`[데이터] 가상 시뮬레이션` · `[AI 협업] 거리-확률 함수 및 시뮬레이션 코드 구현`

가설1(어그로 범위 설계)과 가설2(대처수단 부재)를 독립 요인이 아니라 "구역 설계가
조우 확률을 결정하고, 조우가 곧 스트레스로 이어진다"는 하나의 인과 구조로 통합.
레비아탄 조우를 강제형에서 거리 기반 확률형으로 바꾸면 이탈률이 완화될 것이라는
설계안 시뮬레이션.

## 4단계 — 리뷰 키워드 분석 파이프라인 (`04_review_keyword_pipeline`)

`[데이터] 방법론 시연용 가짜 데이터(mock)` · `[AI 협업] SQL/Python 파이프라인 구현`

Steam 공식 리뷰 API를 활용해 부정 리뷰 내 키워드 언급 빈도를 분석하는 파이프라인을
Python(pandas)과 SQL 두 버전으로 구현. 이 작업 환경은 네트워크가 차단되어 있어
`setup_subnautica2_db.py`의 가짜 데이터로 로직 자체만 검증한 방법론 시연 버전임.

키워드셋은 아래 5단계·6단계를 거치며 다음과 같이 확장됨:
- 최초: 레비아탄, 튕(김), 크래시, 어그로, 최적화
- 습성 가설 배경(생태계 단조로움) 검증용: 단조, 지루, 생태계
- 실측 데이터에서 발견한 비살상 설계 UX 불만: 못죽, 답답, 기절

한국어 활용형 문제(예: "튕김"으로 검색하면 "자꾸 튕겨요"를 놓침)를 고려해 완전한
단어 대신 최소 어근으로 키워드를 정의함.

## 5단계 — 고철 운반형 습성 도입 시뮬레이션 (`05_habit_introduction_simulation`)

`[데이터] 가상 시뮬레이션` · `[AI 협업] 시뮬레이션 코드 구현, 통계 검정 방법 선택 근거 설명`

서브노티카1 미역숲의 추적자(고철더미를 물고 다니다 이빨을 떨어뜨리는 습성)에서
착안해, 비살상 상호작용(먹이/미끼)만으로 자원을 얻는 습성을 서브노티카2 초반
생명체에 도입하면 어떨지 시뮬레이션함. "만족도"는 직접 관측 불가능하므로 "목표
자원 획득까지 걸린 시도 횟수"라는 관측 가능한 행동 지표로 대체.

- 이탈률 차이: 카이제곱 검정
- 파밍 시도 횟수 차이: Mann-Whitney U 검정(분포가 오른쪽으로 치우쳐 있어 정규성을
  가정하는 t-검정 대신 채택 — 근거는 스크립트 주석에 상세 기술)

**결과**: 상호작용을 발견한 유저는 이탈률·시도 횟수 모두 개선되지만, 발견하지
못한 유저는 오히려 습성이 없는 경우보다 더 나빠짐 — 이 습성이 무조건 긍정적인
게 아니라 발견 가능성(discoverability) 설계에 성패가 갈리는 양날의 검임을 확인.
(이는 서브노티카1 스태커 이빨 파밍이 실제로 커뮤니티에서 반복적으로 혼란을
일으켰던 사례를 반영해 설계에 포함시킨 리스크임.)

이 가설은 4단계까지의 시뮬레이션과 달리, **현재 게임에 존재하지 않는 습성을
새로 도입한다는 전제의 사고실험**이라는 점에서 한 단계 더 가상적임을 명시함.

## 6단계 — 실제 리뷰 데이터 적용 (`06_real_data_application`) ★실측 데이터

`[데이터] 실측 Steam 리뷰(1차 n=34, 2차 n=150)` · `[AI 협업] 데이터 로더 구현,
키워드 원문 대조 검증 보조, 결과 해석 및 서술 정리`

`load_real_reviews.py`로 실제 수집한 Steam 리뷰를 4단계 SQL 파이프라인에 그대로
적용. 표본을 2차례에 걸쳐 확장하며 검증함:

| 수집 차수 | 표본 수 | 부정 리뷰 수 | 파일 |
|---|---|---|---|
| 1차(탐색적) | 34건 | 10건 | `raw_data/subnautica2_reviews_2026-08-31.csv` |
| 2차(최종) | 150건 | 57건 | `raw_data/subnautica2_reviews_150_2026-08-31.csv` |

**최종 결과** (`review_analysis_result.txt`, 150건 기준):
- 전체 긍정 비율 62.0% (93건 긍정 / 57건 부정)
- 부정 리뷰 내 키워드 언급: 최적화 5건(8.8%), **못죽 4건(7.0%)**, 레비아탄·어그로·
  답답·기절 각 1건(1.8%)
- "단조/지루/생태계"(습성 가설의 배경이 된 "생태계가 단조롭다"는 가정)는 두 차수
  모두 0건 — 이 배경 가설을 뒷받침하는 실측 근거는 아직 확보하지 못함

**방법론 노트 — 키워드 검증의 중요성**: 1차 수집 이후 공식 키워드셋에 "PC"를
후보로 넣고 2차(n=150) 원문을 직접 대조 확인했음. "PC를 재부팅해야 하는 수준"처럼
하드웨어(컴퓨터)를 가리키는 용례가 확인됐고, 나머지 사례는 자동 키워드 매칭만으로
의미를 단정하기 어려운 다의어였음. 신뢰도 낮은 키워드인 데다 해석이 갈릴 수 있는
민감한 방향으로 오독될 위험까지 있어, 이 키워드는 최종 분석에서 제외하고 분석
범위를 "설계·UX 불만"(못죽/답답/기절)으로 한정함. 자동 키워드 매칭 결과를
맹신하지 않고 원문을 직접 대조해 애매한 키워드를 걸러냈다는 점을 분석 프로세스의
신뢰성 근거로 남김.

### 최종 결론

1.1 패치("공격해도 죽이지 못하고 반응·도주하게 만드는" 비살상 설계)가 실제로
반영되었다는 점에서, 본인이 5단계에서 제안한 "비살상 상호작용 습성" 가설의
방향성(공격이 아닌 상호작용으로 생명체와 관계 맺기)은 실제 개발 방향과 일치함이
확인됨.

다만 실측 데이터를 보면 부정 리뷰의 약 9~10%(못죽·답답·기절 합산)가 "죽일 수
없게 만든 설계" 자체에 불편함을 표하고 있는데, **이 불만들을 원문으로 다시
확인해보면 전부 "적대적인 생명체가 늘었는데 대응 수단이 없다"는 전투 무력감에
대한 것이었음** — "레비아탄한테 계속 죽는다", "물고기한테 맞으면서 피해다녀야
한다"는 식. 반면 5단계에서 제안한 습성은 SN1 스태커처럼 비적대적인 생명체가
자원을 나눠주는 파밍 상호작용으로, 애초에 다루는 니즈 자체가 다름.

즉 **이 두 발견을 억지로 하나의 인과로 엮지 않고 정직하게 분리함**:
- 실측 데이터가 뒷받침하는 것: 비살상 설계 방향은 개발 방향과 일치했지만, 그중
  "위협적인 생명체를 상대할 대응 수단 부재"는 실제 유저 불만으로 확인된 별개의
  이슈임
- 실측 데이터가 아직 뒷받침하지 못하는 것: "위협적이지 않은 생명체와의 파밍
  상호작용이 부족하다"는 습성 제안의 원래 배경(생태계 단조로움)은 이번 리뷰에서
  근거를 찾지 못함(4단계 "단조/지루/생태계" 키워드 0건 참고)

습성 제안 자체는 여전히 "비살상 상호작용을 통해 생명체와의 관계를 다양화한다"는
SN2의 설계 철학과 결이 맞는 제안으로 유효하지만, 이번에 발견한 "못죽" 계열 불만을
그 제안의 직접적인 근거로 사용하는 것은 논리적 비약이라고 판단해 결론에서 제외함.
"위협적 생명체 대응 수단 부재"는 습성 제안과는 별도로 다뤄야 할 과제로 남겨둠.

**이 해석이 반증 가능한 근거였는지 자체 점검**: 만약 부정 리뷰에서 "단조/지루/
생태계" 언급이 다수 발견됐다면, 습성 제안의 배경 가설이 실측 근거를 얻어 결론이
더 강해졌을 것임. 반대로 "못죽" 계열 불만이 전혀 없었다면, 비살상 설계 방향
자체에 대한 유저 저항이 적다는 결론으로 이어졌을 것임. 실제로는 후자만 확인됐고
전자는 확인되지 않았기 때문에, 두 결과를 있는 그대로 분리해서 보고함 — 데이터가
어떻게 나와도 같은 결론(습성 제안이 필요하다)으로 수렴하도록 짜인 서사가 아님을
이 분리 자체로 보여줌. 다만 표본이 작아(한계 참고) 두 판단 모두 표본이 커지면
바뀔 수 있는 잠정적 해석임.

### 한계

- 표본 수(150건, 부정 57건)는 여전히 통계적으로 강한 결론을 내리기엔 작은 규모이며,
  본 분석은 통계 검정이 아닌 기술 통계(빈도·비율) 수준에서만 해석함
- 리뷰 텍스트 기반 키워드 매칭은 다의어·문맥 오독 위험이 있어(위 "PC" 키워드
  제외 사례 참고), 저빈도 키워드는 반드시 원문 대조 검증이 필요함
- **수집 방식 자체의 시점 편향**: `subnautica2_real_data_analysis.py`는
  `filter="recent"`로 최신순 리뷰를 수집함. 지금은 1.1 패치(비살상 설계) 직후
  시점이라, 수집된 리뷰에 이 패치에 대한 반응이 실제 전체 유저 여론보다 과대
  대표되어 있을 가능성이 있음. 즉 "못죽 7.0%"는 SN2 전체 시기에 걸친 대표값이
